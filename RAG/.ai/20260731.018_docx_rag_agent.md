# 20260731.018 — RAG-агент по .docx: чистка проекта и новый пайплайн

## Задача

Убрать из проекта хвосты удалённых ранее агентов, вычистить каталог и построить
RAG-агента по локальной документации в формате `.docx`, работающего исключительно
локально — ClickHouse + Ollama.

## Принятые решения

| Вопрос | Решение |
|--------|---------|
| Парсинг `.docx` | Прямой парсер на python-docx (без конвертации в markdown) |
| Форма агента | Tool-calling агент на Ollama с ограниченным циклом итераций |
| Хранилище | Новая база ClickHouse (`kcoi`), старый `.md`-корпус не трогаем |

## Чистка

Удалено из `.ai/` 26 отчётов, описывавших удалённые LangGraph/ReAct-агенты
(state-формат, промпты, итерации, память агента, сводки). Оставлены только
актуальные MCP-отчёты 015-017.

Из корня удалены: `ips_all.txt` (385 КБ данных), `_QUICKSTART_MCP.md` (дубль
`_MCP_SERVER.md`), `continue.config.example.json` (дубль yaml),
`docs/_find_abbreviation_expansion.md` (вложен в `docs/README.md`),
`requirements_mcp.txt` (зависимости слиты в `requirements.txt`), `logs/no-results.har`.

Из `.env` / `.env.example` / `Settings` убраны мёртвые параметры удалённых агентов:
`PROMPTS_DIR`, `MAX_ITERATIONS`, `AGENT_MEMORY_*`, `OLLAMA_FINAL_MODEL`,
`MAX_CONTEXT_CHARS`, `LLM_LOG_ENABLED`, `hyde_enabled`, `reranker_top_n`,
`memory_max_turns`, `enrich_*`. Из `requirements.txt` убраны `langgraph`,
`flashrank`, `langchain-community`, `langchain-text-splitters`, из `rag_chat.py` —
импорт `chromadb`.

Документация приведена в соответствие с кодом: инструментов не 16, а 13, часть
переименована (`find_relevant_sections` -> `search_section_by_name`,
`find_abbreviation_expansion` -> `search_abbreviation`), инструменты
`exact_search_in_file*` и `find_sections_by_term` больше не существуют.
Исправлены docstring-и `regex_search`: он давно работает через RE2 в ClickHouse,
а не сканирует `.md`-файлы (это описание видит LLM при выборе инструмента).

## Новый код

### chunking.py

Общий контракт чанка для всех форматов: модель метаданных `ChunkMeta` (Pydantic),
счётчики `ChunkIndexer` (chunk_index в пределах section + chunk_type),
`SectionStack` (путь разделов), разбиение по размеру с перекрытием, разворачивание
таблиц в строки. `md_splitter.py` переведён на этот модуль, дублирование убрано.

### docx_splitter.py

Разбор `.docx` через python-docx с тем же контрактом чанка, что и markdown —
схема ClickHouse и все 13 инструментов работают без изменений.

- Обход тела документа в исходном порядке (абзацы и таблицы вперемешку — python-docx
  отдаёт их разными коллекциями, порядок теряется).
- Уровень заголовка: номер в имени стиля (`Заголовок 2`, `Приложение: Заголовок 2`)
  -> стиль названия -> слово «заголовок» без номера -> `w:outlineLvl`.
  Lookbehind не даёт стилю `Подзаголовок` пройти за заголовок.
- Служебные заголовки (`Содержание`, `Оглавление`) закрывают уровень, но в путь
  раздела не попадают.
- Идущие подряд абзацы склеиваются в блок до заголовка/таблицы/лимита размера:
  абзац Word — часто одно предложение, поштучные чанки были бы слишком мелкими.
- Таблицы: первая строка — заголовки, далее `table_full` + по чанку на строку.
- Битые связи пакета (`Target="NULL"` от удалённой картинки) чинятся в памяти:
  зип пересобирается без ссылок на отсутствующие части, исходный файл не меняется.
- Позиции: `line_start`/`line_end` — порядковые номера блоков документа.

### rag_agent.py

Tool-calling агент: LLM в Ollama сама выбирает инструменты, они выполняются против
ClickHouse, результат возвращается модели. После `AGENT_MAX_ITERATIONS` раундов
модель переводится в режим финального ответа без инструментов — зациклиться нельзя.
Результаты инструментов усекаются до `AGENT_MAX_TOOL_CHARS`, из них собираются
разделы-источники для ответа. CLI: `ask` / `chat` / `tools`, флаги `--debug`, `--env`.

### rag_chat.py

Индексация обходит `.docx` и `.md` через реестр сплиттеров, временные файлы Word
(`~$*.docx`) пропускаются, ошибка одного документа не останавливает процесс.
Файловый regex-поиск удалён — он не имеет смысла для `.docx`, эквивалент есть
в `kb_tools` (RE2 в ClickHouse).

## Исправленные дефекты md_splitter (были до рефакторинга)

1. **Тройное дублирование чанков.** Условие `tok.nesting >= 0 and tok.map`
   срабатывало на каждом уровне вложенности токенов (`bullet_list_open` ->
   `list_item_open` -> `paragraph_open` -> `inline`), поэтому один и тот же текст
   индексировался 2-4 раза. Теперь контейнер потребляется целиком, внутренние
   токены пропускаются. На тестовом файле: 15 чанков -> 10.
2. **Grid-таблицы теряли первую строку данных.** Разделитель `+====+` под строкой
   заголовков не распознавался (искался только `-`), из-за чего заголовки
   склеивались с первой строкой данных, и она пропадала.

## Проверка на реальном корпусе

60 документов `.docx` (~39 900 чанков):

| Метрика | До правок | После |
|---------|-----------|-------|
| Файлов разобрано | 59 из 60 | 60 из 60 |
| Чанков без раздела | 12.7% | 1.2% |
| Файлов без структуры разделов | 1 | 0 |

Остаточные 1.2% — абзацы титульных листов до первого заголовка, это ожидаемо.
Рост покрытия дало распознавание корпоративных стилей (`Приложение: Заголовок N`),
восстановление битого пакета вернуло файл «Руководство администратора НШР» (191 раздел).

## Не сделано

Индексация корпуса и сквозной прогон агента не выполнялись: в локальном Ollama
не установлено ни одной модели (нужны `bge-m3` и `qwen3.5:9b`), база `kcoi` пуста.
