## Баг OCR (immich-app/immich#32512)

Симптом: все OCR-джобы падают, в ML `INVALID_ARGUMENT : Got invalid dimensions for input: x ... index: 2 Got: 48 Expected: 224`,
в сервере `Unable to run job handler (Ocr)`.

Причина: при `MACHINE_LEARNING_MODEL_REVISION=main` (по умолчанию) не-китайские модели PP-OCRv5
(`ESLAV__`, `LATIN__`, `EN__` ...) берутся из экспорта RapidOCR с безымянной динамической высотой входа.

Обходной путь (в `docker-compose.prod.yml`, сервис `immich-machine-learning`):
`MACHINE_LEARNING_MODEL_REVISION=v2`. Модели тянутся с HF-ветки `v2`, кэш лежит в `/cache/ocr/<model>/v2`.
Старые OCR-модели в кэше переименованы в `detection.main_20261018` / `recognition.main_20261018`
(после проверки можно удалить). Проверено прямым запросом в `/predict`: 200, "Hello 12345", score 0.95.

После фикса апстримом (релиз выше v3.3.3) переменную можно убрать.
Упавшие OCR-джобы 17-18 октября нужно перезапустить: Administration -> Jobs -> OCR -> режим "Missing".

## Как проверить / где смотреть

- Бэкапы: `K:\immich\upload\photos\backups` (в контейнере `/usr/src/app/upload/backups`).
- Логи Postgres пишутся в файлы: `docker exec immich_postgres ls /var/lib/postgresql/data/log`
  (`docker logs` их не показывает).
- Память WSL: `wsl -d docker-desktop -e sh -c "grep MemTotal /proc/meminfo"`, `docker info --format {{.MemTotal}}`.
- `rgzz-process_frigate_events-1` имеет `restart: unless-stopped` и поднимается сам после рестарта Docker.

## Ловушки

- `Dockerfile.immich-server` собирается от тега `release`, а не от `IMMICH_VERSION`: при `up --build`
  версия сервера может разойтись с ML.
- Рестарт WSL (`wsl --shutdown`) останавливает все контейнеры (immich, frigate, clickhouse ...).
